# trpg-prep（TRPG 备团）

将模组源材料（PDF / 文本）转化为可直接用于主持的三部分备团产物。
本 skill 是程序的运行时组件：分析、生成、迭代的全部 prompt 与 schema 均由此文件及其 schemas/ 目录驱动。

## 工作流（程序按此执行）

1. **摄入**：提取模组文本层，逐页检测文本密度（文本页 / 低文本页 / 扫描页），按章节标题页分块，附录单独标记。
2. **分析（逐块 map）**：对每个分块调用一次模型，抽取结构化事实：地点、NPC、物品、事件、线索，每项必须带来源页码。
3. **合成（知识库 reduce）**：合并各块结果并消歧（同一实体跨页出现时合并信息、页码叠加），构建时间线与情报关系网。
4. **生成（三部分）**：只从知识库生成，不重读全文；三部分互相引用一致。
5. **迭代**：GM 指定某部分局部重生成，只使用「知识库 + 该部分」的上下文，不得推倒其他部分。

## 产物 schema

见 `schemas/` 目录：

- `knowledge.json` —— 中间知识库（分析阶段产物）
- `overview.json` —— 第一部分 故事总览
- `locations.json` —— 第二部分 信息集合
- `encounters.json` —— 第三部分 临场遭遇

## 质量标准（每条均为硬性要求）

1. **事实与推测分离**：每个条目必须标注来源页码；模组原文没有的内容必须放入明确标注的「建议」字段，或用「（GM 建议）」前缀明示。
2. **不发明设定**：不得添加模组中不存在的角色、地点、线索、机构。拿不准时写「未见原文依据」，而不是编造。
3. **保留原名**：人名、地名保留模组原文（中英对照），方便 GM 与模组正文对照。
4. **情报解锁关系**：信息集合必须给出「哪条线索 → 解锁哪个场景 / 哪个 NPC 的秘密」。
5. **坑点提示**：故事总览必须包含 GM 容易漏给的关键线索、容易翻车的判定点。
6. **遭遇三要素**：每个遭遇必须有 触发条件、失败后果、与主线的关联。
7. **分阶段**：遭遇按 开场 / 发展 / 高潮 / 收尾 四阶段组织；模组本身有章节结构时按章节对应阶段。
8. **附录纳入**：附录（报纸剪报、NPC 卡、规则补充）同样参与分析，来源标注「附录 pX」。
9. **扫描页**：低文本/扫描页若含关键内容（如地图、剪报），在对应条目中提示「原文为图片页 pX，建议 GM 查原 PDF」。

## 输出原则

- 结构化 JSON 为唯一源；UI 渲染为可编辑卡片。
- 支持导出 Markdown 打印，供桌上使用。
- 生成物默认语言跟随模组语言；模组为中文时用中文输出，保留原文名。
