# TRPG Prep 第三次方向重评

更新时间：2026-08-28  
状态：**当前有效；取代 2026-08-27 维护记录中“重建产生平行书架”和“大事实集独立出卡后直接合并”的临时判断。**

## 1. 触发问题与实测结论

《奈亚拉托提普的面具》第一章 p96-180 的真实试用暴露了四个问题：旧书架难以管理、200+ 候选批量复核报错、机械窗口几乎都显示“标题分页”、284 条事实无法生成备团产物。

本轮用正式数据库和 ASGI 调用复核后确认：

- 普通书架已经具备重命名与删除能力；内置种子保持只读。此前现象更可能来自旧前端资源或种子项目边界。
- 101 条候选直接提交会触发 FastAPI 的列表上限校验；旧前端把结构化校验对象转成字符串，因而显示 `Error: [object Object]`。这不是“任务总候选不能超过 100 条”。
- 奈面任务保存了 42 个历史窗口；当前固定核心页策略会得到 29 个窗口。重复页眉仍会被标记成标题信号，因此“标题边界”不能解释为章节或场景边界。
- 奈面书架有 284 条已提升事实，直接 JSON 约 152,000 字符。简单拆成两个独立产物请求虽然绕过单次输入上限，却会丢失跨批次人物、地点、线索和时间关系。

## 2. 已确认决策

### 2.1 项目与分析版本分离

书架代表 GM 的备团项目；一次 PDF 分析只是项目内部的分析版本。

- 初次创建任务时建立项目 ID，并创建分析 `v1`。
- “按当前切分重新分析”沿用同一个书架 ID，创建 `v2/v3...`，保留旧候选、复核历史和已提升事实。
- 新旧分析版本可以对照，但不会在书架列表制造平行项目。
- 删除书架时清理它拥有的全部分析版本；删除单个分析版本不自动删除已经提升的事实。

### 2.2 机械窗口不声明语义边界

机械切分只保证：

1. 所选页范围无遗漏地被核心页覆盖；
2. 相邻页作为重复上下文保护跨页事实；
3. 每条候选归属唯一核心页并保留多页来源；
4. 字数截断、窗口范围和重试均可审计。

页眉、句末和续写迹象只能作为诊断信号，不能命名为章节、地点或场景边界。场景/实体聚类属于后续 LLM 候选整理和 GM 复核层。

### 2.3 大事实集采用分层生成

大范围产物生成采用“局部压缩 + 全局规划 + 回读原始事实落卡”，而不是各批独立出最终卡片：

1. 按来源顺序把事实分成有界批次。
2. 每批只生成带事实 ID 的局部备团单元摘要，例如场景材料、人物功能、线索簇、威胁、时间线和结局材料。
3. 全局请求读取所有紧凑单元，只负责对齐实体、处理跨批关系并规划最终卡片及其事实 ID。
4. 每张计划卡重新读取它引用的原始已提升事实，生成最终字段；局部摘要不成为新的事实来源。
5. 服务端校验卡片与字段来源；全部成功后才写入书架。

小事实集仍可直接生成，避免无意义增加请求。任务必须显示“局部整理 / 全局编排”阶段和进度。

### 2.4 批量复核保持任务级操作

- 前端必须正确展示 FastAPI/Pydantic 的结构化错误。
- 超过单请求上限时由产品自动分批，GM 不负责手工拆分。
- 分批过程保留已处理进度；重试不得把“总量超过 100”误报成候选内容错误。

## 3. 对 2026-08-27 临时实现的处置

| 临时实现 | 处置 | 原因 |
|---|---|---|
| 书架重命名/删除 | 保留并补多分析版本级联测试 | 符合项目所有权 |
| 前端 100 条分批与错误格式化 | 保留并用 284 条精确回归 | 直接解决真实故障 |
| 固定核心页 + 相邻上下文 | 保留 | 满足覆盖和跨页保护 |
| “标题边界”作为窗口标签 | 改为机械原因；标题仅可作为非语义诊断信号 | 避免把重复页眉误当场景边界 |
| 重建创建新任务和新书架 | 改为同书架的新分析版本 | 防止项目列表碎片化 |
| 各事实批次独立生成最终卡片再合并 | 替换为局部单元压缩 + 全局规划 + 原始事实落卡 | 保留章节级关系，且不让摘要替代事实 |

## 4. 本轮验收

- 对同一项目重新分析后，书架列表仍只有一个项目，任务显示递增分析版本。
- 284 条候选可以从任务级队列批量接受，不出现 `[object Object]`。
- 新机械窗口只显示固定页数、字数上限或范围末端等真实切分原因；不把页眉称为场景/章节边界。
- 284 条事实走至少两个局部批次、一次全局规划和原始事实落卡；最终产物保留事实与字段来源，任一阶段失败不写入半套卡片。
- 使用隔离 FakeLLM 完成确定性回归，再用当前真实上游在数据库副本上验证一次大事实集流程。

## 5. 开发边界

- 本轮不扩展三板块的卡型档案。
- 本轮不要求 GM 手工拆章节来适应模型上下文。
- 本轮不把机械窗口升级为自动场景切分器。
- R2 的候选拆分、合并、冲突标记和完整多来源编辑仍待后续完成。
- 正式 `code-review` 技能需要 Git 固定点与 `docs/agents/issue-tracker.md`；当前目录二者均不存在，因此本轮只记录手工 Standards/Spec 审计，不伪造分支审查结果。
