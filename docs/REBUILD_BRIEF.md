## 产品判断

旧工具把模组改写成另一份静态文档，但真正需要的是把素材拆成可调度单元，再按规则和现场需要组装。

核心公式：

> 规则无关事实库 + 可插拔规则档案 + 场景/角色/威胁卡 + 现场调度面板。

四层职责：

1. **素材层**：保留原文、页码、图片页提示，绝不把模型补写伪装成原文。
2. **事实层**：地点、人物、线索、事件、秘密、时间线、利害、障碍、可行动入口。
3. **规则层**：不同规则定义不同的风险、行动、失败、揭示、战斗和调查方式。
4. **桌面层**：GM 在跑团中打开的是卡片、线索网、时钟、提示和即兴问题，不是一篇长文。

## 多规则档案

### 档案职责

每个 Rule Profile 是一份声明式配置，不只是一个 prompt：

- 定义核心行动类型：调查、社交、探索、冲突、仪式、追逃等。
- 定义风险来源：理智、暴露、伤势、资源、时间、关系、恐怖升级。
- 定义失败语义：前进但有代价、错过信息、威胁推进、局面恶化。
- 选择要生成的卡型：场景、NPC、威胁、环境、时钟、证据链。
- 提供现场 GM 移动和即兴问题。
- 决定导出排版，但不决定底层数据结构。

### Cthulhu Dark / COC 转现代叙事

目标不是给敌人做面板，而是把调查压力、恐怖、信息揭示和不可逆后果变成可操作卡。

场景卡字段：

- 一眼可讲的画面。
- 玩家能立刻做的事。
- 场景中的直接线索与隐藏线索。
- NPC 只保留功能性信息：身份、目的、能给什么、要什么、施压点、被逼后的后果。
- GM 移动：追问、暴露、误会、代价、时间推进、威胁接近。
- 失败或冒险的后果，而不是单纯“检定失败”。
- 出场条件与退场条件。
- 原文页码。

### 三角机构作为参考范式

三角机构不是本项目要实现的第三种运行档案。它只提供一种值得借鉴的组织方式：场景材料本身可以直接支撑桌边叙事，NPC 只保留功能，线索不必依赖复杂扮演逐个挤出，主持人也不需要先准备一整套玩家行动菜单。

这类“低备团、场景驱动”的优点会影响通用整理和场景计划的设计，但不会被编码成三角机构专属字段、规则按钮或运行模式。

### Daggerheart 式环境/敌人

不是复刻官方排版，而是把旧 DND/COC 遭遇翻译成叙事调度卡。

环境卡：

- 可利用物。
- 危险物。
- 移动、视线和距离关系。
- 环境变化。
- 战斗外的解决入口。

敌人卡：

- 意图。
- 标志性行动。
- 危险前兆。
- 压力或受伤后的变化。
- 撤退、谈判、仪式中断等非互殴解法。
- 原数据块只作引用，不强迫 GM 前置读完。

## 数据骨架

规则无关事实：

```ts
{
  id: 'fact_001',
  source: { file: '奈亚拉托提普的面具v1.0.pdf', page: 12 }
}
```

补充字段：

```ts
{
  text: '原文事实或明确标注的 GM 建议',
  kind: 'clue | npc | location | event | threat | stakes | obstacle | timeline',
  visibility: 'explicit | hidden | inferred | gm_suggestion',
  links: ['fact_002']
}
```

规则档案：

```ts
{
  id: 'cthulhu-dark-2e',
  name: 'Cthulhu Dark 2E',
  card_types: ['scene', 'npc', 'threat', 'clock'],
  risk_axes: ['exposure', 'insight', 'pursuit'],
  failure_moves: ['cost_forward', 'reveal_pressure', 'threat_advance'],
  gm_moves: ['ask_question', 'raise_stakes', 'advance_offscreen_clock']
}
```

派生卡：

```ts
{
  id: 'card_001',
  profile_id: 'cthulhu-dark-2e',
  type: 'scene',
  facts: ['fact_001', 'fact_004'],
  edit_state: 'generated | edited | approved'
}
```

硬性原则：

- 原文事实与 GM 建议分离。
- 每条关键信息保留页码。
- 卡片由多个事实合成，但每张卡能回溯来源。
- 同一事实可以被不同规则档案渲染成不同卡。
- 手工编辑优先级高于生成结果。

## 新界面

主界面不是“生成三件套”，而是战役工作台：

1. **书架**：上传模组、规则、附录和图片。
2. **事实网**：线索、人物、地点、事件、利害的关系图/列表。
3. **卡组**：按场景、旅程、威胁、NPC、环境生成和编辑卡。
4. **运行模式**：选择 Cthulhu Dark / Daggerheart 运行档案；通用整理档案只参与素材整理和转换。
5. **桌面视图**：当前场景、已揭示线索、未引爆钩子、时钟、GM 移动、即兴问题。
6. **导出**：Markdown 或打印卡组；导出只是副产品。

## 下一步实现顺序

1. 用按页准备向导从真实 PDF 选择一个小范围。
2. 逐页人工确认地点、人物、线索、事件和压力事实。
3. 检查事实来源、可见性和卡片引用，再保存领域覆盖层。
4. 从确认卡片编排一份场景计划，GM 手工修订节拍。
5. 用一次真实 Cthulhu Dark 游戏记录翻页点和遗漏。
6. 根据运行记录调整字段；暂不接入 LLM 或批量自动理解。
