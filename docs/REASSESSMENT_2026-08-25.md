# TRPG Prep 方向重评与开发计划

更新时间：2026-08-25  
状态：**历史方向稿；2026-08-26 起由 `REASSESSMENT_2026-08-26.md` 取代阶段顺序和完成判断。三板块产物原则仍可追溯使用。**  
范围：产品模型、三板块产物、LLM 介入边界、试点路线与验收标准。

## 1. 先给结论

项目不应继续追求“上传长模组，一次生成固定三件套”。这条路径把三个不同问题混成一次不可审计的文本生成：理解原文、把事实转换成规则语义、为某一场游戏编排现场节奏。它在短样例上容易看起来完整，在 660 页战役上却会同时放大遗漏、幻觉、过度准备和错误的线性剧情假设。

产品应改定义为：

> **一个以来源可追溯事实为底座、由 LLM 协助整理、由 GM 审核转换、按一次游戏场景运行的备团工作台。**

“卡片”是桌边调度视图，不是产品本体；“场景包”是一次可运行的最小交付物；“战役事实库和章节索引”是长期资产；“LLM”是候选内容生产器，不是裁判或自动主持人。

## 2. 为什么现在必须停下来重评

### 已观察到的事实

- 仓库同时存在旧的 `campaign -> analyze -> generate` 三件套管线和新的 `SourceFact -> RuleProfile -> DerivedCard -> ScenePlan -> SessionState` 领域管线。
- 新工作台已经能保存事实、卡片、场景计划和运行状态，但事实仍偏向单一来源引用，缺少系统化的证据状态、模型运行记录和复核队列。
- 旧 `backend/app/analyze.py` / `generate.py` 的产物是 `overview`、`locations`、`encounters`；它们与新领域包不是同一数据契约。继续在旧管线上堆功能会产生两套互相竞争的产品。
- 奈面 660 页的真实需求不是“读完后得到一篇摘要”，而是跨章节的背景、NPC 功能、地点、线索、支线、时间压力、结局与下一站选择；一次场景只应加载其中的可运行子集。
- 参考材料显示，不同规则对卡片需求不对称：奇幻冒险依赖环境和敌人意图；现实恐怖依赖线索、恐怖递进和功能 NPC；三角机构式材料可以直接从场景运行，但不应被误做成第三套规则。

### 当前判断

继续扩大卡型或接入更强模型，不能解决上述边界混乱。下一步必须先统一“事实是什么、谁审核、何时可运行、不同板块为何需要不同产物”。

## 3. 产品对象与分层

```
源文件/页 -> 证据与事实库 -> 通用备团资产 -> 目标规则运行素材
                                      -> 场景包 -> 桌边运行状态
```

### 3.1 源文件与证据层

保存 PDF、页码、文本片段/图像页提示、章节范围和导入版本。它回答“原文在哪里”，不回答“GM 应该怎么跑”。

### 3.2 事实层

保存地点、人物、线索、事件、物件、威胁、利害、障碍、时间压力及其关系。每条事实必须区分：

- 原文明确写出；
- 可由多处原文支持的推断；
- GM 创作建议；
- 尚未确认的模型候选。

### 3.3 通用备团资产层

把 D&D、COC 等旧模组压缩成规则无关的“可转换材料”：场景情境、人物功能、威胁逻辑、线索网络、时间线、分支/入口/出口和来源缺口。它不启动桌边规则，也不替 GM 决定玩家路线。

### 3.4 目标规则运行层

将已确认资产解释成 Cthulhu Dark 或 Daggerheart 的桌边语义。不同规则可以从同一事实派生不同卡，但不能凭空增加事实。

### 3.5 场景包与运行层

场景包是一次游戏的工作集：当前情境、所选卡片、节拍、线索揭示、时钟、GM 移动、退场条件和下一拍钩子。运行状态记录现场发生了什么，不修改源事实。

## 4. 三个板块的产品定义

三个板块是**内容/转换目标**，不是强制生成三套固定卡片。每个项目根据素材和目标规则按需产出卡型。

### 4.1 奇幻冒险

目标：把 D&D 或其他传统奇幻模组转换成 Daggerheart 风格、能应对玩家偏航的场景调度材料；不复制官方版式，也不把所有 NPC 变成完整敌人面板。

最小产物：

- **冒险框架**：前提、玩家目标、主要阵营/冲突、可接受的多种结局。
- **场景/遭遇卡**：开场画面、场景目标、利害、入口、可改变的条件、节拍、退场/转场条件。
- **环境卡**：可利用物、危险物、位置/距离、环境变化、非战斗出口、视觉化提示。
- **意图敌人卡**：当前意图、标志性行动、危险前兆、被压制/受伤后的变化、撤退/谈判/仪式中断等解法、原数据块引用。
- **阵营/关键角色卡（按需）**：姓名、动机、当前资源、会提供/阻止什么、对玩家选择的反应。普通路人只留在场景 roster，不单独制卡。
- **遭遇钟/倒计时**：援军、警报、追击、崩塌、仪式、目标移动等，并写明如何推进与触发后果。
- **奖励/后果卡（按需）**：胜利不只等于清空敌人，还包括情报、盟友、资源、位置变化和新的硬选择。

不默认生成：每个怪物的完整数值卡、每个 NPC 的长篇背景、唯一解流程、玩家行动菜单。

### 4.2 现实恐怖

目标：服务 Cthulhu Dark 优先，也能承接 COC 模组的调查素材；把恐怖和调查压力做成“渐进、可揭示、可后果化”的运行包，而不是把怪物面板当主产物。

最小产物：

- **谜团简报**：hook、主题、权力关系、最终恐怖、调查员为何在乎、允许的调查方向、战役级后果。
- **地点/场景卡**：感官开场、玩家已知、可从现场得到的线索、NPC 入口、不断加深的恐怖意象、威胁如何回应、退出/转场。
- **功能 NPC 卡**：身份、目的、知道/提供什么、隐瞒或误导、施压点、被逼后的变化；只有会改变调查方向的人物才单独出现。
- **线索/证据卡与线索网**：线索原文、来源页、直接/隐藏/推断状态、指向何处、失败时如何继续给信息、可被哪些场景揭示。
- **恐怖/威胁卡**：主题、征兆、表现层级、逼近方式、对调查员的反击、不可逆后果、非战斗出口；不强行生成敌人数值。
- **压力/追击/仪式钟**：暴露、追捕、时间窗口、理智/洞察代价或世界变化；每个阶段都必须有可描述的现场变化。
- **章节/单元包**：背景（GM-only）、本单元开始状态、场景顺序只是建议、NPC/线索索引、可能收束、未回收线索和下一章入口。
- **玩家展示材料**：报纸、信件、地图、照片等作为独立 handout，标记玩家可见性，不混入 GM 机密。

不默认生成：把每个神话生物都做成战斗面板、把所有线索锁在检定后、预写调查员必须走的路线、把 GM 背景直接显示给玩家。

### 4.3 通用备团

目标：为旧模组建立可追溯、可转换、规则中立的资产；它是“转换工作台”的材料层，不是第三个运行规则。

最小产物：

- **模组/章节地图**：章节、页码、前置、入口、出口、可跳过/可回收单元、跨章依赖。
- **场景整理卡**：当前情境、玩家可能到达的入口、可发现内容、压力、关键角色、障碍、后果、来源范围。
- **人物/阵营功能卡**：角色在信息、关系、资源、威胁或时间上的功能；不预设扮演风格。
- **威胁逻辑卡**：表现、意图、前兆、升级、限制、解决路径和原始数据引用。
- **线索/知识图**：事实之间的支持、矛盾、指向和解锁关系。
- **时间线/事件卡**：不行动时会发生什么、触发条件、可被玩家改变的节点。
- **转换问题清单**：缺页、矛盾、规则专属字段、需要 GM 决定的价值判断；未解决项不能被模型悄悄填平。

## 5. LLM 的新定位

本轮不再把“暂不接入 LLM”作为永久产品原则，但也不把旧 LLM 路由直接接回工作台。新的原则是：

1. LLM 只生成**候选**，不直接写入已确认事实。
2. 每个候选都带来源页/片段、证据类型、置信度、模型与 prompt 版本。
3. 只有经 GM 审核的事实才能参与运行卡和场景包。
4. 模型不能替玩家决定行动，不能把唯一剧情路线当作事实。
5. 生成失败、JSON 截断、来源不足、实体冲突和模型不一致都要进入可重试/可人工处理的队列。
6. 运行时问答只能检索已批准材料；若没有依据，明确回答“未在已批准资料中找到”。

具体管线见 [LLM 管线与人工复核](./LLM_PIPELINE.md)。

## 6. 验收指标

先测真实 GM 工作，不先测模型“文采”。每个指标都要在人工基线与 LLM 辅助版本之间比较：

- **准备时间**：从选定页范围到能开始一场 2 小时游戏的总时间。
- **桌边检索时间**：需要找一条线索、一个 NPC 动机或一个时钟时，平均多久能找到。
- **来源覆盖率**：运行卡中的关键事实是否全部可回溯到页码/片段。
- **无依据内容率**：候选阶段和 GM 审核后分别统计；审核后不得有未标记的模型创作冒充原文。
- **复核负担**：每张卡需要 GM 修改多少字段，哪些字段最常被改。
- **偏航承受力**：玩家采取未预设方案时，GM 是否仍能从卡上得到可用的动机、环境和后果。
- **跨场次连续性**：上一场揭示的线索、时钟和 NPC 状态能否在下一场正确恢复。
- **信任度**：GM 是否愿意在没有回看原 PDF 的情况下使用该卡；若不愿意，记录原因。

硬门槛：关键运行卡 100% 有来源或明确 GM 创作标记；未审核候选不得进入运行；任何新功能都不能让 GM 阅读量增加而没有可量化的桌边收益。

## 7. 分阶段计划

### 阶段 A：契约封存

- 以本文件、`ARTIFACT_CONTRACTS.md`、`LLM_PIPELINE.md` 取代旧三件套作为产品依据。
- 明确旧 `analyze/generate` 为兼容遗留代码，不再新增字段或 UI 依赖。
- 给领域模型补充证据状态、来源片段、生成运行和复核队列前，先写最小 JSON 夹具与校验规则。

### 阶段 B：奈面单章人工金标准

- 继续使用 PDF 159-165 页“恐怖的咀咀屋”。
- 将现有 20 条事实和 7 张卡重编为一个现实恐怖单元包：谜团简报、地点/场景、功能 NPC、线索网、威胁、时钟、结局/后果和 GM-only 背景。
- 由 GM 实际运行至少一次，记录翻页、遗漏、重复和玩家偏航。

### 阶段 C：同章 LLM 影子模式

- LLM 对同一页范围生成候选事实和卡草案，但不写入运行包。
- 与人工金标准做 diff：漏事实、错误归因、无依据推断、实体合并错误、过长字段。
- 只有当来源覆盖率和复核负担达到可接受水平，才把候选接入工作台审核队列。

### 阶段 D：现实恐怖短模组复验

- 使用《无光的灯塔》20 页作为第二个真实样本，验证线索网、恐怖升级、追击、场景收束和可选延长内容。
- 重点检查：没有敌人卡时，运行器是否仍能支持威胁；失败是否继续给信息；结局是否能容纳玩家不同选择。

### 阶段 E：奇幻冒险垂直切片

- 使用《狂野逐羊》6 页，先手工建立环境、意图敌人、场景、遭遇钟和后果卡。
- 再从《龙金劫》选一段包含事件顺序、阵营响应或哨站的短范围，验证多阵营、动态环境和非线性入口。
- 不在此阶段批量转换 D&D 全书；只验证“卡片是否减少桌边查找”。

### 阶段 F：扩大到战役级

- 只有前述短样本都通过，才把奈面扩展到章节级索引、跨国旅行、支线、长期时钟和多结局。
- 再评估 Daggerheart 转换是否真的减少阅读/查找；若只是把原文重新排版，停止扩展。

## 8. 明确暂停的工作

- 不实现三角机构专属运行规则。
- 不批量把所有 COC/D&D 模组转成 Daggerheart 卡片。
- 不让 LLM 未经审核地事实化奈面 660 页。
- 不把玩家行动菜单或预写对白作为产品输出。
- 不新增没有真实试点场景的规则档案。
- 不继续扩展旧 `overview/locations/encounters` 三件套 schema。
