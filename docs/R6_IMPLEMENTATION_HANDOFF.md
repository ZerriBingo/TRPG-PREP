# R6 第一切片：书架可用状态与打开失败原因一致

状态：R4 已独立签收并同步两工作区。下一轮先完成这一有明确复现的 R6 切片；R7 拆分与旧运行入口退役暂不实施。

## 已复现的问题

临时库中实际 HTTP 结果：

| 合成项目 | GET /api/domain/workspaces | GET /api/domain/workbench |
| --- | --- | --- |
| 有效 location 项目 | validation_error=null | 200，可读取 |
| 结构合法但仍用旧 scene 卡型的项目 | validation_error=null，未标识不可用 | 422，工作区无效、卡型未定义 |

get_domain_workspaces 只做 ExampleBundle.model_validate；打开还做 validate_bundle，两者判断不同。前端 userFacingError 又可能把确定的契约不兼容压成“所选内容已变化，请刷新后重试”，刷新不能解决此问题。证据在 output/r4-review-20261031-190659/r6-availability-evidence.json，不依赖真实历史库。

## 目标与边界

GM 在书架能识别项目目前为何不能按当前契约打开；直接链接或刷新失败时也看到准确原因，并能回书架选择其他项目。原项目内容保留，不给出“刷新即可修复”的假指引。

- 核对列表、打开及错误展示的实际链，复用已有领域校验、validation_error 等表达；不新增状态平台、迁移框架或修复向导。一个无效项目不得让整个书架失败或消失。
- 区分模型结构错误、卡型/板块契约不兼容及临时请求失败，提供可行动原因。必要时用最小稳定错误类别，保留维护诊断；不把原始 JSON、堆栈、参考规则内部 ID直接当 GM 提示。
- 列表与打开按同一份当前契约判断。合法空项目、尚未生成资料、待审核卡片和有效批准项目仍可读；不把“尚未运行”误作“项目损坏”。
- 无效项目保留可识别记录和既有允许的管理入口；不自动删除、覆写、修复、重新生成或再次提升成新项目。保留种子项目显式测试访问边界。
- 核对初始化、书架切换、刷新三个真实入口；失败后不将上个项目内容误标成失败项目数据。失败时应仍可返回书架，不因尚未绑定事件而失去导航；按实际证据作最小修正。
- 保持 R1 资料/来源解耦、R2 批准检索、R3/R5 选择/世界隔离和 R4 规则边界。不顺带重写前端、删除旧 beat/章节/剧情线或改变任务所有权。

## 验收与交回

1. 临时库覆盖正常、合法空、待审核、旧卡型但结构合法、模型结构无效五类项目。列表保留应保留项目，正常项目不受牵连；列表状态与打开结果一致。
2. 真实浏览器从书架选择及直接 URL 打开无效项目，准确显示原因，能返回书架打开有效项目；失败前后原 bundle、事实、准备选择、SessionState 不变。正常项目仍可读取、续团及恢复选择。
3. 临时服务错误允许合理重试；持久不兼容不提示“刷新修复”。不能用一个文案替换全部错误，也不能为了隐藏 ID丢掉错误类别。
4. 聚焦回归覆盖实际 HTTP 校验与错误/导航事件，至少一个反例在修正前失败；仅断言文案或 mock 新状态不算解决。外层临时存储保护 Python 脚本；不读取业务正文、不调用模型。
5. 交回改动、复用接口理由、前后证据、回归与限制，更新 audit/backlog 后交 Sol 复审。保留其他未提交维护，不提交、推送或发布。

renderRuntimeLegacy、旧 beat 路径和共享 LLM 接口仍为后续 R6/R7 候选。退役先核对调用、测试、保存数据及外部依赖，不能把“有旧名”当作可删证据；真实旧项目迁移另行限定对象和验收，本轮不自动迁移。
