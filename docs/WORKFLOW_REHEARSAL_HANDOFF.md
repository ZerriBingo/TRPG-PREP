# 下一轮：隔离预演双板块验收入口与操作

验收准备已签收，见 `WORKFLOW_ACCEPTANCE_REVIEW.md`。本轮把 `WORKFLOW_ACCEPTANCE_PACKAGE.md` 变成可重复执行的预演，先发现上传、审批、查阅与保存恢复的真实操作障碍。只处理合成材料，不调用真实模型或修改生产功能。

## 具体交回

1. 从验收包两个“合成原文”小节提取原文与稳定锚点，各自生成可提取中文文字的 PDF；不把问题、答案边界或评分表放进模型输入。记录本地路径、SHA-256、页码→H-S/F-S 锚点对照；抽取回读确认无丢段、乱码或意外夹带答案。可用现有 PDF 工具，不新增产品导入方式。
2. 复用既有导入隔离与临时浏览器服务方式，提供一条明确可运行的本地启动命令。单独临时 DB_PATH/UPLOAD_DIR、固定回环端口、清晰清理方式，并验证正式库摘要不变。临时配置强制 Fake，禁止继承正式密钥或连接真实上游。运行文件与结果置于忽略的 output 目录；可复用的少量维护代码经复审再决定是否入 scripts。
3. 从当前真实 UI 上传两个 PDF，按已有入口选全范围、建立两个板块任务并执行已有整理/审批流程。Fake 若不支持某步骤或不生成本例内容，准确记录到达位置和原因；不得偷偷注入手工卡或改数据库，再声称从上传端到端通过。若需手工合成运行包验证后半段，应单列为“注入夹具的运行演练”，与上传/Fake 链严格标注，不将其计为生成质量。
4. 在可运行的后半段验证：问题所需支持资料和来源可从运行页查阅、未选资料检索、可达场景自由切换、准备选择保存/重载、继续游戏与显式重开的状态边界。记录真实 UI/HTTP 证据、来源锚点对应与不能回答的问题；可给代理实际操作时长，但评分表中的真人备团/现场计时保持未测。实际卡内容若不是由两个样例生成，不能按样例题宣布答对。

## 交回结论

用一份精简记录列出两板块各阶段“到达/未到达/为何”、复用脚本与命令、输入/输出证据、手工干预和可复现障碍。没有障碍也要明确 Fake 能证明什么、下一次真实生成还需什么，避免继续只写验收文档。发现缺口先给复现和小范围修复建议，本轮不擅自扩生产范围。

真实模型生成和真人演练是之后的证据层，按届时授权执行；本轮不读取正式业务正文、不使用真实上游、不替用户填写真人评分。保留其他未提交维护，不提交、推送或发布。更新 audit/backlog 后交独立复审。
