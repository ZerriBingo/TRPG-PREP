# 参考材料研究笔记

本笔记记录观察和设计启发，不把参考作品的版式直接复制成产品要求。页码均为项目 `Resource/` 中 PDF 的 PDF 页码；网页标题按页面当前中文标题记录。

## 1. 匕首之心：运作一场游戏

来源：官方中文 HTML SRD，页面标题“运作一场游戏”，URL：`https://daggerheart.cn/SRD/running-a-game/`。

### 与备团直接相关的章节

- **游戏主持人守则**：以虚构为始、合作、提出问题并吸收答案、每次掷骰都重要、玩下去看看会发生什么、轻抓故事脉络。
- **游戏主持人实践**：推动故事发展、切入精彩时刻、告诉玩家角色本该知道的内容、以动机赋予世界真实感、运用片段与蒙太奇。
- **应避免的误区**：场景拖沓、唯一解思维、过度预设剧情、总是告诉玩家掷什么骰。
- **游戏主持人行动**：在失败、恐惧结果、明显风险或玩家把焦点交回 GM 时，用软/硬行动推进局势。
- **使用恐惧点**：恐惧是跨场次资源；不同场景规模有不同张力预算。
- **倒计时**：标准、动态、后果、进度、循环、递增/递减、联动和长期倒计时。
- **运行 GM NPC**：关键 NPC 的最小要素是姓名、描述、动机；只有需要机械互动时才增加特性。
- **Additional GM Guidance / STORY BEATS**：准备改变叙事轨迹的节拍，而不是预写具体交换和台词。
- **PREPARING COMBAT ENCOUNTERS / BATTLES AND NARRATIVE**：敌人、环境和危险应服务故事功能；战斗应揭示世界、目标或人物，并由动机驱动。
- **CRAFTING SCENES / PHASED BATTLES / USING DOWNTIME**：场景开场要给可感知信息，中段可改变环境或对手，低强度段落提供恢复和玩家自主框景。

### 设计结论

奇幻冒险卡不应是“敌人属性表的另一种排版”，而应把场景目标、环境变化、敌人意图、危险前兆、硬选择和倒计时放在同一运行上下文中。GM moves 和故事节拍是共同骨架；规则数值是 profile 的局部字段。

## 2. Cthulhu Dark 2E

来源：`Resource/Cthulhu Dark - Rules (2E).pdf`。

### 关键章节

- **Director's Section / Writing a mystery**（PDF p24-35）：谜团由 hook、主题、威胁、最终恐怖、调查员约束、地点、人物、反复出现的恐怖意象和逐步升级组成。
- **Locations / People**（PDF p30-31）：地点应回答调查员到哪里、看见什么、下一步可能去哪里；人物以姓名和少量可表演特征承载信息与互动。
- **Creeping Horrors / Building the horror**（PDF p32-34）：恐怖从模糊、遥远、可疑逐渐变清楚、接近并造成影响。
- **The horror pushes back / Scenes of horror**（PDF p35）：威胁应主动影响心智、身体、关系或环境；恐怖场景可以在不同地点适配。
- **Playing the mystery / Scenes / Adapt the mystery / Take notes**（PDF p40-50）：主持人准备的是可调整的谜团和场景，不是不可改变的路线；结局与后日谈要处理未完事项。

### 设计结论

现实恐怖需要独立的线索/证据层和恐怖递进层。场景卡不能只写“这里有线索”，还要写线索如何继续导向下一问题，以及失败如何用代价、暴露或威胁推进而不是让调查停死。NPC 卡保留功能，不把所有人物写成长传记；威胁卡描述表现和反击，不默认数值化。

## 3. 奈亚拉托提普的面具

来源：`Resource/奈亚拉托提普的面具v1.0.pdf`。

- **运行本战役 / 准备游戏**（PDF p26-29）：要求主持人理解重点场景、线索意义、章节材料和 NPC；建议把关键 NPC、事件和展示材料独立整理，便于快速查阅。
- **战役考量**（PDF p26-29）：章节可被跳过、重排或以后作为独立冒险使用；不能强迫调查员按书中顺序走。
- **章节结构**：背景信息、当地教团、出场人物、地点/调查、支线、尾声、人物与怪物数据分布在同一章，但桌边查阅需要重新组合。
- **“恐怖的咀咀屋”**（PDF p159-165）：一个短范围同时包含调查入口、功能 NPC、仪式/暴露压力、威胁、结局和不可逆后果，适合作为首个运行包。

### 设计结论

奈面验证了“章节不是运行包”。应将 GM 背景、可查地点、NPC 功能、线索网络、时钟、结局和玩家 handout 拆分，再按本次场景选择；跨章节依赖要在 `module_map` 中保留。

## 4. 无光的灯塔

来源：`Resource/无光的灯塔.pdf`。

- 地点调查把平面、物件、尸体、日志、无线电、天气和可见痕迹组合成线索链。
- 威胁不是一张“敌人卡”就能表达：幼徒有前兆、追击、弱点、数量调节和不同的战斗/逃生选择。
- 守秘人笔记允许根据团体口味延长围攻或提前收束；结局包括死亡、日出、救援、求援后的审问与后日谈。

### 设计结论

现实恐怖板块必须支持“同一地点多种压力强度”和“可选延长”。线索、威胁、环境和结局应互相链接，运行器要能记录玩家选择，而不是把模组固定为唯一场景顺序。

## 5. 狂野逐羊

来源：`Resource/狂野逐羊.pdf`。

- 模组明确按地点、遭遇和关键剧情组织场景。
- NPC 段落同时给出动机、谈判可能、突然攻击、追逐和战斗地点对环境的影响。
- 关键选择包括救援、跟随、欺骗、追逐、魔杖风险和多种后果；结尾不只奖励金币，也有关系和后续承诺。

### 设计结论

奇幻冒险的最小切片应把“场景 + 环境 + 意图敌人 + 关键 NPC + 后果/时钟”放在一起。若只把文本拆成地点卡和怪物卡，会丢掉追逐、谈判、环境利用和危险提示。

## 6. 龙金劫重置版

来源：`Resource/【彩页译文】龙金劫重置版.pdf`。

- 章节含事件顺序、阵营哨站、响应队伍、查探机会、地图情报、敌人分组名册和不同时间状态。
- 设计强调阵营会响应玩家，而不是等待玩家进入一个固定战斗房间。
- 同一地点在宴会、仪式、抢劫或警报状态下有不同 roster 和目标。

### 设计结论

长篇奇幻模组需要“状态化场景”和“阵营响应”资产。场景包应记录当前状态、触发事件和可变 roster；敌人卡不应脱离阵营意图和环境阶段单独生成。

## 7. 三角机构与卡面参考

来源：`Resource/三角机构收容库.pdf`、`Resource/三角机构场景卡.jpg`、`Resource/匕首心环境卡、敌人卡 (1-5).JPG`。

- 三角机构场景卡的视觉重点是一个可直接讲述的现场、当前人物/异常、调查入口和分层信息；它不要求为每个 NPC 建立复杂面板。
- 匕首心环境/敌人卡把动机/战术、危险前兆、动作/反应、环境变化和 GM 自问问题放在同一张高密度卡上。
- 这些材料证明“卡片可以承载现场调度”，但不证明所有规则都应使用相同卡型。

### 设计结论

借鉴组织密度和问题提示，不复制第三套规则。三角机构的低备团、场景驱动方式应影响通用备团层；匕首心的意图/前兆/环境结构应影响奇幻冒险层；两者都不能覆盖现实恐怖的线索网和恐怖递进需求。

## 8. 证据等级

| 等级 | 用途 |
|---|---|
| A | 规则书/官方 SRD 明确的主持原则或数据结构 |
| B | 真实模组中反复出现、且能解释桌边负担的组织方式 |
| C | 单个模组或卡面中的可借鉴范式，不应直接升格为通用 schema |
| D | 本项目的待验证假设，必须通过真实跑团或对照测试 |

本轮产品契约中的共同骨架主要来自 A/B；具体卡型组合和字段密度仍属于 D，须由奈面、无光灯塔和狂野逐羊三个短样本验证。
