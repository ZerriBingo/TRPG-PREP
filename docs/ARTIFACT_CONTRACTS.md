# 三板块产物契约

本文件定义“什么值得生成”。它不是 UI 组件清单，也不是要求每个项目拥有全部卡型。板块选择决定默认模板，素材内容和目标规则决定最终实例。

## 1. 共同字段

所有板块资产都应尽量提供：

| 字段 | 含义 |
|---|---|
| `id` / `title` | 稳定标识和 GM 可读标题 |
| `purpose` | 这份资产在桌边减少哪一种负担 |
| `source_refs` | 页码、片段或图片页；没有来源的字段必须标为 GM 创作 |
| `visibility` | `gm_only`、`player_safe`、`handout` 或 `mixed` |
| `evidence_status` | `source_fact`、`inference`、`gm_authored`、`model_candidate` |
| `linked_assets` | 关联事实、地点、人物、线索、时钟和场景 |
| `review_state` | `candidate`、`needs_review`、`approved`、`edited`、`retired` |
| `open_questions` | 仍需 GM 决定或原文缺失的内容 |

共同硬规则：资产不能把推断伪装成原文；不能在没有来源的情况下补全规则数值；不能用一个长摘要替代可检索字段。

## 2. 奇幻冒险模板

### 必选核心

#### `adventure_frame`

- 一句话前提
- 玩家角色当前目标
- 主要阵营及冲突
- 可能的成功/失败/妥协结果
- 本单元与更大冒险的连接

#### `scene`

- 开场画面
- 场景目标与利害
- 玩家可能从哪里进入
- 现场正在发生什么
- 至少两个可回应的方向
- 场景变化/节拍
- 退出或转场条件

#### `environment`

- 可利用物与有利位置
- 危险物与危险前兆
- 移动、视线、距离或地形关系
- 玩家行动后环境如何改变
- 战斗外解决入口

#### `enemy_intent`

- 当前意图，而不是“它是什么种族”
- 标志性行动与可读前兆
- 对玩家目标的干扰方式
- 受伤、失势、失去领袖或谈判时的变化
- 撤退、投降、交换、仪式中断等解法
- 原始数据块引用（若目标规则确实需要）

#### `countdown`

- 名称与起始阶段
- 什么行为推进它
- 每个阶段可描述的变化
- 触发后的后果
- 是否可暂停、重置、转化或被玩家改变

### 按需生成

- `character_function`：只有会改变目标、资源、关系或时间的人物。
- `faction_response`：有多个阵营会主动响应玩家时使用。
- `journey_or_downtime`：跨地点旅行或长休整本身构成选择时使用。
- `reward_consequence`：奖励/代价会改变下一场时使用。

### 不生成

- 每个普通 NPC 的独立卡。
- 只有数值没有意图/前兆的敌人面板。
- 预写玩家台词、唯一解路线、逐轮战术脚本。

## 3. 现实恐怖模板

### 必选核心

#### `mystery_brief`

- hook
- 主题与反复出现的恐怖意象
- 最终恐怖（GM-only）
- 权力/资源关系
- 调查员为什么会在乎
- 开放的调查方向
- 失败、妥协和战役级后果

#### `investigation_scene`

- 感官开场
- 玩家角色合理知道的事实
- 直接线索与可选深入线索
- 现场人物和他们的目的
- 恐怖征兆的当前强度
- 威胁如何回应拖延、调查或暴露
- 离场、转场和未解决问题

#### `clue`

- 玩家可看到/听到的内容
- 来源和证据状态
- 它支持或反驳什么
- 指向的下一地点、人物或问题
- 不应因一次失败而永久丢失的核心信息
- 可采用的代价式揭示方式

#### `functional_npc`

- 身份和第一印象
- 想要什么
- 能提供什么
- 隐瞒/误导什么
- 施压点
- 被逼到极限后的行动或后果

#### `horror_threat`

- 主题连接
- 早期、接近、显形三个以上表现层级
- 可重复的 creeping horror 线索
- 对调查员、地点和关系的反击
- 最终恐怖如何逐步变清楚
- 逃离、交易、牺牲、延迟或其他非战斗出口

#### `pressure_clock`

- 暴露、追击、仪式、援军、资源耗尽或世界变化
- 推进条件和每阶段现场表现
- 触发后果
- 玩家改变时钟的手段

### 按需生成

- `chapter_packet`：跨多场游戏的章节背景、NPC/线索索引、结局和下一站。
- `handout`：玩家会直接阅读的信件、报纸、地图、照片或记录。
- `survival_encounter`：威胁必须以战斗/追逐呈现，且需要桌边快速查阅时使用；仍不等于完整敌人卡。

### 不生成

- 把所有线索绑定到检定成功。
- 把 GM 背景、最终恐怖或隐藏 NPC 动机混入玩家展示材料。
- 默认给每个神话存在制作数值面板。
- 用线性“正确顺序”替代线索网络和开放入口。

## 4. 通用备团模板

### 必选核心

#### `module_map`

- 章节/场景层级
- 页码范围
- 前置与可跳过关系
- 入口、出口和转场
- 跨章依赖
- 可独立运行的最小单元

#### `scene_extract`

- 原文情境
- 玩家可能做什么（描述入口，不写菜单）
- 可发现内容
- 障碍和压力
- 角色/阵营功能
- 后果和分支
- 来源与未决问题

#### `character_function` / `threat_logic`

只描述跨规则稳定的功能：信息、资源、关系、意图、前兆、升级、限制、退出和非唯一解。规则数值留给目标运行档案。

#### `clue_graph` / `timeline`

把事实之间的指向、支持、矛盾和时间推进显式化，供不同目标规则重新渲染。

#### `conversion_questions`

记录“需要目标规则或 GM 决定”的问题，例如：是否需要敌人卡、某个 NPC 是否重要、某个检定失败应转为代价还是信息、原文缺失哪张地图。

### 不生成

- 通用板块自己的桌边行动按钮。
- 通用板块直接启动 `ScenePlan`。
- 伪装成原文的规则转换结论。

## 5. 产物选择算法（概念）

1. 先用一个或多个 `PageSpan` 表达 GM 选择的跨页章节范围，再建立 `module_map`；模型处理窗口不得被当作章节或场景边界。
2. 抽取/确认事实与关系，标记证据状态。
3. 根据目标规则和本次场景目标选择模板。
4. 只实例化被至少一个已确认事实支持的卡型。
5. 将多个卡编排成 `ScenePlan`，由 GM 审核后进入 `SessionState`。
6. 运行后把实际揭示、时钟变化和遗漏记为反馈，不回写成未经核实的原文事实。
