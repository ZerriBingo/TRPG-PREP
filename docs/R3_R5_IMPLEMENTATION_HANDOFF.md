# R3/R5 最小实现交接：保存并取回本次材料选择

状态：流程原型 v2 与本轮正式切片均已签收、同步两工作区，保持未提交。首次五项 P2 及复审收尾、实际证据和局限见 R3_R5_IMPLEMENTATION_REVIEW.md。以下保留本轮验收范围；下一轮见 R4_IMPLEMENTATION_HANDOFF.md。

## 本次确定的行为

GM 可以在一个已有项目的当前板块内，从已批准资料中挑选这次可能用到的材料，显式保存，刷新或关闭重开项目后取回，并在继续游戏时从运行页快速查阅。一次只维护该项目、该板块的一份当前选择，允许替换、移除、保存空清单；不增加历史版本、日程或多人协作。

保存的是卡片引用，展示始终读取当前批准版本并保留原文来源。准备选择不规定玩家行动顺序，不成为运行可达性的门禁。未选资料仍可从 R2 的项目内速查取回；计划或章节外资料仍只查阅、说明切换原因。保存或清空准备不能修改计划成员、运行位置、触发、线索、时钟、备注或运行日志。

这是对“准备成果之后还能用”的最小落实；不需要先测出重复劳动达到某个阈值才允许保存。内存 A 保留为尚未保存的编辑状态，不作为正式交付终点。复用计划的持久化基础，但不把所选 ID 覆写进 ScenePlan.card_ids，也不把 SessionState.notes 当作编码存储。

## 实现边界与复用

- 从两边已经同步的当前工作区开始，保留所有历史未提交维护。先阅读 R2 签收记录、R3_R5_WORKFLOW_PROPOSAL.md 及 R3_R5_WORKFLOW_REVIEW.md 的最终签收说明。
- 已核对 ExampleBundle 具有 cards、plans、profiles 等项目数据，通过 storage.save_domain_bundle 保存；ScenePlan.card_ids 决定运行集合，SessionState 另行保存。采用项目 bundle 中一个默认空、可选兼容的板块到卡片 ID 列表字段，或同样简单且有明确证据更适合的既有项目存储位置；首选不新增表、迁移框架、会话准备实体或通用任务引擎。具体字段名由实现者按现有命名选择，并在交付说明中解释。
- 保存只更新准备选择。复用现有 bundle 读写和校验基础，检查现有整体保存接口会覆盖哪些其他编辑；若不能安全地只改选择，可增加一个狭窄的选择更新入口，在最新项目内容上更新该字段，不能用旧的前端整包覆盖资料和计划。失败时保留未保存选择、显示失败并可重试，不显示假成功。
- 旧项目缺字段视为空选择，不要求重抽取或迁移历史资料。选择按真实项目 ID 与板块 ID 隔离。服务端验证项目内、对应板块、明确批准及唯一的卡片 ID；不信任前端传入的正文、状态或别的项目资料。不把选择错误升级为整个项目不可读。
- 已保存卡片随后被编辑为待审批、删除或替换时，加载与展示须安全：不泄漏新草稿，不按同名自动重连，清楚提示所选引用已不可用并允许移除/重新选择。不能因残留引用阻断项目或既有资料复核。保存、删除、复核等写回路径要保留彼此的字段。
- 在现有产物/准备入口提供选择、查看详情、移除和明确“保存本次准备”；复用已有字段、来源和可靠关系，不另做抽取、生成或运行页面。不要为了模仿原型的三栏外观复制整个前端。
- 在现有运行页增加已保存选择的快捷区或筛选入口，能打开当前批准卡详情并返回当前情境；不因选择清单变小而隐藏全部速查。时钟仍复用原有访问与操作入口。板块差异由已有卡型展示表达。
- 继续仍走已保存 SessionState 的恢复路径，不调用 startPlan/resetSession。重开保持显式确认，并准确列出会重置的触发、线索、时钟、备注、日志与位置；取消无副作用。准备选择应在续团与明确重开后保留，只有清空准备并保存才移除它，防止为了重跑世界而损失阅读取舍。
- 未保存更改需有可见提示。若导航/刷新会丢失，说明并采用现有合适的未保存处理；不要默认自动保存覆盖服务器数据。不得把原型固定运行章节的示意规则替换到真实 runtimeNarrative 筛选里。
- 本轮不做卡片正文编辑、GM 笔记新体系、来源/卡型迁移、复杂比较工作台、自动遭遇编排、运行规则数值、R4 或 R6/R7 重构。原型比较和关系展示可指导使用现有详情；本轮验收重点是选取、保存、取回与状态隔离。

## 必须验证的端到端行为

使用合成资源、临时数据库；真实前端事件与 HTTP 路径不能仅用 HTML 字符串代替。

1. 现实恐怖：从当前地点查 NPC 的诉求和现场信息，选择两个地点/人物资源，保存。刷新及关闭重开项目后仍可取回，保留来源；未选人物仍可搜索，查阅后能回原情境。
2. 奇幻：使用已有可靠关系或结构从主线/势力发现情境与对手，选择场景和可选遭遇资源并保存，在运行页取回；仍能查未选替代资料。若当前真实契约不支持原型的 related 字段，使用已存在的关系并说明缺口，不能凭合成原型声称真实模型已经支持。
3. 保存前后对比 SessionState 全字段及 ScenePlan 的成员/锚点集合完全不变；继续不新增日志/不丢状态，准备预览不改位置。运行页合法切换仍改变位置和日志，章外/计划外只读说明仍有效。
4. 两项目/两板块互不串选择。旧项目无字段可读。重复/别项目/别板块/未批准/未知 ID 的保存被明确拒绝或按既有约定处理，绝不显示为批准内容。已保存卡片退回审核、被删后不泄漏草稿且项目仍可读。
5. 保存失败保留待保存选择；重试成功后准确反映状态。保存空清单只清空选择；续团、确认重开、取消重开不误清准备。实际刷新确认持久化，不能用“模拟刷新”证明。
6. 检查修改字段经现有卡片审核、删除、计划保存/删除等受影响写回路径不丢失，不用旧整包覆盖并行更新。测试与变更对应，只扩展受影响路径，不跑真实模型或重新生成全库。

交回：变更清单、字段/入口选择与复用理由、临时存储与浏览器证据、聚焦回归结果、遗留限制。不要提交、推送或发布；完成后交 Sol 独立复审。首次整理和每次准备时间分开测量，本轮不声称达到一小时准备两小时游戏。
