# 2026-08-27 任务级复核与产物后台任务维护记录

## 触发问题

本轮真实试用暴露了三个工作流问题：

1. 候选复核只能按单个分析窗口操作，跨窗口的同一备团任务需要反复切换。
2. 狂野逐羊在书架生成备团草案时同步等待模型并发生超时，页面无法恢复任务进度。
3. 运行工作台把未揭示线索正文藏在按钮之后，GM 看不到应当掌握的披露记录。

## 已落地决定

### 1. 复核范围以备团任务为主

- 候选筛选增加“备团任务（全部窗口）”选项，值为 `prep:<job_id>`。
- 该范围通过 `/api/domain/prep/jobs/{job_id}/candidates` 汇总任务下所有窗口的候选；来源页筛选仍只是定位器。
- 新增 `POST /api/domain/prep/jobs/{job_id}/candidates/review`，批量复核前校验所有候选确实属于该任务。
- 单个分析窗口仍保留，用于失败重试和精确定位，不再是唯一批量入口。

### 2. 产物生成改为可恢复后台任务

- `POST /api/domain/examples/{example}/cards/draft` 立即返回 `202` 与 `job`，不再让 HTTP 请求同步等待模型。
- 任务状态持久化在 SQLite `artifact_jobs` 表，可通过
  `GET /api/domain/examples/{example}/cards/draft-jobs/{job_id}` 查询。
- 状态包含 `queued/running/completed/failed`、卡片数量、待确认问题和可读错误；刷新页面后仍能恢复排队或失败状态。
- 真实模型产物请求的读取超时提高到 300 秒，并透传到独立 worker；默认请求仍保留 120 秒兼容旧调用。
- 只有后台任务完成后才把卡片写入书架；写入前后都会重新加载并校验工作区，避免覆盖人工修改。

### 3. 线索正文与揭示状态分离

- 运行模式始终显示线索正文。
- 未揭示线索显示“未揭示”和“标记已揭示”；已揭示线索显示“已揭示”和“已记录”。
- `revealed_clue_keys` 与运行日志仍是唯一状态来源，GM 是否已向玩家披露不再决定正文是否可见。

### 4. 补齐跨页来源筛选

- 复核页的来源页输入支持单页、范围和离散页，例如 `4-6, 8`，也兼容 `p4-p6`。
- 候选只要任一 `source_refs.page` 与输入范围相交就会保留，跨页候选不再需要逐页切换。
- 无效表达会在输入框和候选区明确提示，不再伪装成“当前页已处理完”。

## 本轮维护：书架生命周期、大批量复核与大事实集

### 1. 书架项目可管理

- 普通任务书架支持重命名；名称只改变展示字段，不改变项目 ID、来源 PDF、页范围、板块或任务上下文。
- 普通任务书架支持删除；删除会同时清理运行状态、产物生成任务、候选提升审计和对应备团任务/影子候选。
- `red_signal_fixture` 与 `naimen_pilot` 等内置种子项目保持只读保护，接口和 UI 都会明确拒绝删除/重命名。

### 2. 200+ 候选批量复核

- 后端继续保持每次最多 100 条的请求上限，防止单次请求过大。
- 前端“复核所选”自动按 100 条分批提交，并显示已处理进度；200 条以上不再因为校验上限中断。
- FastAPI 数组校验错误统一格式化为字段位置和可读消息，不再显示 `Error: [object Object]`。

### 3. 机械分页边界

- 核心负责范围固定优先使用页数/字符预算；扫描 PDF 中重复页眉被识别为标题时，不再强行把窗口缩成单页。
- 标题只作为边界审计提示，跨页事实仍通过相邻上下文、核心页归属和多页 `source_refs` 保留。
- 以《奈亚拉托提普的面具》p96-180 验证，窗口由逐页碎片收敛为稳定的三页核心窗口（末段不足三页时收尾），不再被每页页眉切碎。

### 4. 大事实集产物生成

- 产物任务先按当前 `PrepJob` 的来源文件与选定页范围过滤事实，避免把其他章节混入模型输入。
- 事实按约 80,000 字符预算拆成多个模型批次；每批独立生成草案，服务端合并重复卡并保留字段来源/待确认问题。
- 所有批次完成并通过最终契约校验后才一次性写入书架，避免半套卡片被误认为完整结果。
- `ArtifactDraftJob` 持久化 `fact_count`、`batch_count`、`completed_batches`，刷新页面可看到进度；若批次失败，书架不会写入部分产物。
- 事实在进入批次前按最早来源页排序；每批提示模型这是完整范围的传输分批，并要求把跨批次关系留在 `open_questions`，不跨批次臆造引用。
- 单条事实超过单批输入上限时直接失败并给出“拆分或缩短后重试”的可读原因；模型失败会标明第几批，便于重新提交。

### 5. 旧任务按当前切分重建

- 任务列表会将持久化窗口与当前分页算法重新比较；即使历史任务的 `window_strategy` 字段相同，只要实际窗口不同，也会显示“按当前切分重建”。
- `POST /api/domain/prep/jobs/{job_id}/rebuild` 会创建新的任务并自动开始，旧任务、候选、复核记录和原书架事实全部保留，不做原地改写。
- 新旧任务使用不同的任务 ID 和书架 ID，GM 可以先对照候选质量，再决定是否继续使用新任务；源 PDF 不存在或任务正在运行时不会提供可执行重建。
