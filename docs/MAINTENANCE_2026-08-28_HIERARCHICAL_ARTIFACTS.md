# 2026-08-28 分析版本与分层产物维护记录

## 触发问题

奈面第一章 `p96-180` 的真实试用产生了 284 条事实，并暴露出四类问题：书架项目管理、200+ 候选批量复核、机械窗口语义误导，以及大事实集无法可靠一次生成产物。

## 已落地决策

- 书架是 GM 的备团项目；一次 PDF 分析是项目内部版本。重新分析沿用 `workspace_id`，递增 `analysis_version` 并保留旧审核历史。
- 机械切分只保证核心页覆盖、相邻上下文和可审计预算。标题、续写与句末只作为 `boundary_signals`，不得称为章节、地点或场景边界。
- 大事实集采用“局部整理 -> 全局规划 -> 回读原始事实落卡”。局部摘要只帮助规划，不替代已提升事实。
- 候选复核由前端按 100 条分批；服务端接受最多 1000 条以兼容旧缓存页面，并把 Pydantic 错误格式化为可读消息。

## 持久化与恢复

`artifact_job_steps` 以阶段、步骤序号和输入哈希记录每次模型调用。每一步保存全部 attempt、原始响应、错误与规范化输出。重试同一任务时，已成功且输入未变的步骤直接复用，只重新执行失败步骤。最终卡片全部通过确定性校验后才一次写入书架。

## 本轮故障修复

真实测试中，上游在局部整理第 2 批遗漏了一个合法的已提升事实 ID。原实现把“模型未归类”误当成硬失败，导致整批任务停止。现改为为每个遗漏事实创建可追溯的“待整理事实”兜底单元，保留原文、来源页和待确认问题，再交给全局规划决定是否落入最终卡片；未知 ID、越界引用和结构损坏仍然硬失败。
