# 产品护栏与决策记录

状态：当前执行中的产品约束（2026-08-26 第二次重评后）。任何新功能、数据模型或界面流程都必须先符合这里的约束；如果需求与约束冲突，暂停实现并向项目负责人确认。完整方向以 `docs/REASSESSMENT_2026-08-26.md` 为准。

## 产品中心

本项目的中心不是复刻某一种现代规则的卡片排版，而是减轻长模组在桌边运行前的阅读与组织负担。

当前优先服务两条桌边运行路径：

- Cthulhu Dark：现实恐怖、调查压力、线索揭示、关系与不可逆代价。
- Daggerheart：奇幻冒险、环境调度、敌人意图、位置变化与硬选择。

三角机构不是第三种桌边运行模式。它在项目中只作为参考范式：说明一种可以直接从场景材料运行、无需复杂 NPC 扮演和提前备团的组织方式。

## 三层边界

原文与事实 -> 通用模组整理 -> 目标规则运行素材 -> 场景计划 -> 桌边运行

- 事实层不绑定规则，保留来源页码、可见性和事实/推断/建议的区别。
- 通用模组整理层负责压缩 D&D、COC 等旧模组的地点、人物功能、威胁逻辑、时间压力和来源结构。
- 运行档案只负责把已确认素材解释为 Cthulhu Dark 或 Daggerheart 的桌边语义。
- 整理档案不能直接生成或启动桌边场景计划。
- 目标规则中已有的官方卡片或模组结构不应被无意义地重复拆解；只有当转换能减少运行负担时才新增整理工作。

## 谨慎原则

- 不把三角机构的“无需备团”范式误做成需要实现的规则系统。
- 不因为 Daggerheart 有环境卡和敌人卡，就默认所有规则都需要同样的卡片。
- 不为 Cthulhu Dark 强行制作敌人数值面板；应优先整理威胁表现、意图、恐怖、线索和后果。
- 不把模组原文、人工推断、GM 建议或模型生成内容混在一起。
- 不把长 PDF 自动改写成一篇更长的摘要；任何整理结果都必须有明确桌边用途。
- LLM 只能生成带来源的候选或检索式辅助；未经人工复核不得进入运行包。必须保留原始输出、模型/prompt 版本、失败状态和可重试路径。
- GM 选择的是章节或一个/多个跨页备团范围；模型抽取窗口和单页证据引用不能冒充用户的内容范围。
- 复核队列、生成器、卡片视图或运行器没有自然上游/下游时，只能标记为组件完成，不能标记为产品完成。
- 每个阶段必须从空白数据库按用户界面完成真实工作流；直接注入夹具或手写 API 只算自动化测试。

## 必须暂停并询问

遇到以下情况，不继续猜测或扩展实现，先向项目负责人提问：

1. 不确定某种规则应被当作运行档案、整理档案还是仅作参考范式。
2. 不确定一个字段是给 GM 内部使用，还是会被直接展示给玩家。
3. 不确定某段内容是原文事实、可验证推断还是 GM 创作建议。
4. 发现新功能可能让 GM 需要阅读更多内容，而不是更少。
5. 发现目标规则已经有足够好的官方模组结构，新增转换层可能只是重复劳动。
6. 需要选择自动推断还是人工确认，且两者会影响事实可信度。
7. 需要大规模修改数据模型、删除现有素材或改变当前工作流。
8. 测试结果与产品语义冲突，即使代码技术上可以运行。

提问时必须说明当前观察到的事实、至少两种解释或实现方向、各方向的影响，以及在得到确认前暂停哪一部分工作。

## 当前明确不做

- 不实现三角机构运行档案。
- 不把所有 COC 或 D&D 模组批量转换成 Daggerheart 卡片。
- 不对奈面 660 页全文做未经人工确认的事实化处理。
- 不把玩家端行动菜单作为产品输出。
- 不为了证明多规则能力而新增没有真实使用场景的规则档案。

## 当前下一阶段

只推进一条可验证的小路径：从空白工作台选择真实 PDF 与跨页范围 -> 调用已配置模型 -> 生成候选 -> GM 复核并提升事实 -> 生成现实恐怖单元包草案 -> GM 审阅并运行。具体阶段、板块契约和停止条件见 `docs/REASSESSMENT_2026-08-26.md` 与 `docs/IMPLEMENTATION_BACKLOG.md`。

在这条路径被真实使用并确认有效前，不扩展新的规则档案，不把 LLM 候选直接写入运行包，也不做批量章节自动理解。下一阶段是 R1“空白数据库到真实候选”，不是继续单独扩展影子复核组件。
