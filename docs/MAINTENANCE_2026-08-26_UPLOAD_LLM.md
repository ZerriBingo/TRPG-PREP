# 2026-08-26 PDF 上传与 LLM 响应维护

状态：已实施并通过自动化、浏览器和真实模型单窗验证。

## 用户反馈

- 备团任务直接列出 `Resource/` 与 `data/` 中的 PDF，像开发资料扫描，不像正常产品入口。
- “本次目标”“GM 备注”和任务模型均为自由输入，普通用户不太会修改，也可能造成提示漂移。
- 新上游能返回内容，但多个窗口显示大量校验错误。

## 根因

工作台此前把项目内置参考 PDF 与用户上传文件放在同一个任务下拉框中。任务还允许覆盖目标、备注和模型，导致同一板块任务难以保持可重复。

新配置的 `deepseek-v4-vision` 连接正常且可列出模型。失败窗口的原始响应已经包含候选，但常见字段采用了模型自选的简写：

- `source_refs: ["p5", "p6"]` 或 `[7, 8]`，而正式 schema 要求来源对象。
- `confidence: "high"` 或 `"高"`，而正式 schema 要求 `0..1` 数字或 `null`。

因此问题不是传输失败，而是提示词没有给出足够精确的 JSON 示例，接收层也缺少网关适配。

## 实施决策

### PDF 来源

- `POST /api/domain/source-files` 分块接收 PDF，限制 512 MB，校验扩展名、PDF 文件头、加密状态和页数。
- 新任务下拉框只列出 `data/uploads/`；`Resource/` 仅保留给既有样例和手工来源回看。
- 上传成功后自动选中新文件，并显示页数与原文件名。

### 任务输入

- 用户只选择已上传 PDF、跨页范围、目标板块和固定时长。
- 后端按板块与时长生成并持久化任务指令。
- 任务使用当前模型连接配置，不接受任务级模型覆盖。
- 请求契约不再接受自由目标和 GM 备注；这不是仅隐藏前端字段。

### 响应适配

`prep` 调用 `shadow.submit_shadow_result` 时提供专用转换器。影子 API 默认仍保持严格，不影响既有隔离测试。

允许的确定性适配：

- `p5`、`page 5`、`第5页`、整数 `5` 转为当前任务文件的来源对象。
- 窗口内的简单页段如 `p5-p6` 展开为两个来源对象。
- 来源对象缺少 `file` 时补为当前任务文件。
- `high/medium/low`、`高/中/低` 不伪造精确数值，转为 `null`。
- 数字字符串和百分比转为明确的 `0..1` 数值。
- 已知中文事实类型映射到正式 `FactKind`；单个链接/问题字符串包装为列表。

仍然拒绝：

- 任务窗口之外的页码。
- 与任务文件不一致的来源文件。
- 含糊页码文本、过长页段、未知字段或无法解释的结构。
- 不符合正式候选 schema 的其他内容。

## 验证

- `scripts/test_prep_job.py` 现在覆盖 PDF 上传、来源分组、系统目标、跨页窗口和松散模型格式适配。
- 影子任务、候选 diff、复核持久化和证据边界测试全部通过。
- 桌面与 390px 浏览器验证通过，无页面横向溢出或控制台错误。
- 使用正式配置数据库副本和 `deepseek-v4-vision` 运行《无光的灯塔》`p4-7`：任务 completed，17 条候选，引用仅在 `p5-p7`，2 条候选有多页来源。

正式数据库中的旧任务保持 cancelled，维护没有自动重跑多个模型窗口。GM 可在工作台点击“重试失败页段”；旧详细错误默认折叠，只显示可理解摘要。
