# R6 后续：旧运行渲染入口的依赖核查与最小清理

前置：书架可用状态切片已签收，见 `R6_IMPLEMENTATION_REVIEW.md`。两工作区保留此前未提交维护；本轮不开始共享 LLM 接口拆分或通用任务引擎。

## 已有证据与范围

仓库源码搜索目前只找到 `frontend/workbench.js` 中 `renderRuntimeLegacy()` 的定义，未发现调用。现用的 `renderRuntime()`、`renderBeat()`、`changeBeat()`、计划预览和章节/剧情线检索仍有调用及测试，不能把它们都视为同一段死代码。旧卡型项目仍按当前契约标记不可打开，不在此轮迁移。

下一轮先核实 `renderRuntimeLegacy` 的直接/动态调用、内联事件、测试截取、构建/打包及文档/外部使用约定。若确认没有可达消费者，可删除该函数以及证明仅由它使用的局部辅助内容；交回每项删除依据与前后回归。若发现消费者，记录证据并保留有关入口，不扩张为整个旧运行模型退役。

## 必须保留

- 自由地点/环境切换、批准资料检索、来源查看、准备选择、继续游戏与显式重开语义。
- 仍在使用的章节、跨章剧情线、已有计划与会话字段、旧 beat 的数据读取和 API。此切片只清理已证实不可达的前端实现，不删除模型字段、旧存档、后端端点或生成路径。
- R6 的错误原因、行身份与导航保护，包括保存失败不被后台重绘吞掉。不顺手重排整份前端、改样式、引入模块加载器或新的兼容层。

## 交回与验收

1. 简短列出候选函数的调用/消费者证据、删除或保留理由和实际改动；不要只以 `Legacy` 命名或文件长度判断。
2. 用合成项目验证现实恐怖、奇幻的查阅、任意场景切换、续团和准备选择；对涉及的旧 beat 分支跑已有合成契约，不能以删测试或改预期掩盖行为变化。
3. 重跑相关 Node 检查、JS 语法及领域/运行聚焦 Python；Python 外层临时存储隔离，不读业务正文、不调用真实模型，正式库摘要保持不变。
4. 更新 audit/backlog 后交独立复审。保持两工作区其他未提交维护，不提交、推送、发布。R7 的接口拆分待此轮证据确定后单独限定。
