## 4. 可重复的演练步骤

### 4.1 入口与一次性整理

先将 1.1 和 2.1 的原文分别制成 PDF，仅包含原文与来源锚点，不含问题表和期望答案。记录文件 SHA-256、页码→锚点对照，人工确认文字可提取、无丢字。原文当前不直接作为粘贴输入进入产品；应使用既有 PDF 上传入口。

使用单独应用进程，在导入/启动前为 `storage.DB_PATH` 和 `storage.UPLOAD_DIR` 指定临时目录；固定本地端口并记录地址。不得把临时 UI 指向正式库。现有导入隔离和合成浏览器启动脚本可复用，避免另写产品入口；临时目录由演练脚本管理并清理。

真实模型请求须在其授权范围内执行，本次文档与字段检查不发请求。取得实际新输出后，从上传 PDF、选全范围、建立板块任务、抽取、候选复核/提升、产物生成到审批各阶段留证；奇幻如流程要求结构整理，照现有步骤完成并记录，不跳过为手工卡片。分别记录主动阅读、调整/复核、模型等待和墙钟总时长，一次性整理单独归档。

检查字段回答与原文、事实引用关系。所有手工修订保留前后差异；模型原输出和人工审批后结果分别评分。手工填写/Fake 夹具可用于演练 UI，但记录为“合成流程演练”，不计作真实生成质量证据。

### 4.2 每次备团

开始条件是已完成并审批的同一项目。GM 从确定本次可能需要的资源起计时，保存本次准备；记录选择/调整次数、阅读/查找/复核时间、等待及墙钟时间。重开项目取回选择，并检索一处未选材料；确认可查阅，若不在当前计划中不能切换，应有明确只读说明。

完成一次续团，核对已保存位置、笔记、日志、钟与线索。完成原状态的记录后，在演练项目执行一次显式重新开始并核对第 3 节预期；不要把这次故意清状态的操作计入普通备团耗时。两种操作后的准备选择都应保留。

### 4.3 现场查阅

记录员按 H1–H10 或 F1–F10 提问（F4/F10 支持卡型算同一道题）。GM 仅用运行页及其检索、来源入口回答，不返回事实管理/产物编辑补材料；查看原始 PDF 时如实记一次返原文，不能既禁止返回又不计无法回答。每题记录时间、实际卡/字段、回答是否可直接使用及引用是否支持。

记录员中途要求改去未选地点/环境，并问“如果跳过主任/税所/救信使，下一步还有什么可运行”。GM 应可依世界目标和资源回应，不需要预写玩家决定。自由切换后保存、刷新及续团，核对状态；不按问题表顺序强制玩家行动。
