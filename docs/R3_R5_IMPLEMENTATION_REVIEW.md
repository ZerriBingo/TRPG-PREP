## 代码规范轴

独立审查提出四项 P2，均由父代理进一步复现，属于实际正确性缺陷，无需因它们另建工程框架。

1. **P2：慢保存吞掉请求之后的材料改动。** frontend/workbench.js:3715、3747–3775。保存时只禁用“保存/清空”，卡片加入、列表移除及 togglePrepSelection 仍可用；响应将请求结果无条件覆写 draft 并将 dirty 设为 false。真实浏览器：保存地点 A，拦住 PUT；此时再加 NPC，草稿为 [A,NPC]、dirty=true；释放请求后变成 [A]、dirty=false，界面显示“已保存 · 1 张”。这是用户已做选择被静默丢弃。
   - 修正：保存期间冻结该份选择的所有编辑入口，或以请求快照/修订号区分已提交与后续草稿，保留后续改动及未保存提示。不能只禁一个按钮。
   - 回归：真实事件链在延迟 PUT 时加入、移除、切板块；成功和失败均不能吞改动或清错 dirty。现有立即返回的 mock 不覆盖这个问题。

2. **P2：已保存时钟的快捷按钮无详情。** workbench.js:3786–3813、4341–4345、4432–4434。服务端及产物页允许时钟加入，但运行快捷区为 clock/operation_clock/encounter_clock 一律生成 data-retrieval-card；普通详情资格经 runtimeSearchCards 排除这些类型。真实浏览器保存地点与 clock，刷新后显示已保存 2 张；运行页点击 Review Clock 后 selected 为 card_review_clock，详情为空，没有原因或有效后续动作。
   - 修正：时钟快捷入口复用既有时钟访问/定位，或明确提供适合的只读说明；若该钟不在当前运行范围，解释边界。不能生成无效的普通详情按钮，也不能重置或另建一套时钟。
   - 回归：批准的三类时钟覆盖实际快捷点击；非时钟卡仍可打开详情与来源、返回当前情境；不因快速访问改变时钟阶段或日志。

3. **P2：窄保存接口仍会在并发下覆盖另一份已成功选择。** backend/app/main.py:1816–1824；storage.save_domain_bundle 将整份 JSON 覆盖。重新读取最新内容与之后写入并非原子更新。两个同步端点可在线程池并行执行：请求分别读到旧 bundle，各只改自身板块再写全包，最后一个写入覆盖先一个板块。
   - 独立 HTTP 复现：在临时合成库中，读取后用 barrier 对齐两个 PUT（现实恐怖与奇幻），两者均 HTTP 200；最终 prep_selections 只有现实恐怖一项，奇幻的已成功保存丢失。这是可到达的多标签页/并行请求情境，不涉及部署或新增多人功能。
   - 修正：为本轮新增的字段更新提供原子性或检测冲突，保护已有卡片/计划/复核/删除写回与它交错时不覆盖彼此。采用现有存储中的有界更新、事务或版本校验机制即可；不要扩展成通用任务引擎或全项目存储重写。
   - 回归：实际并行两板块 PUT，结果同时保留；选择与受影响审核/删除/计划写回交错时保留彼此结果，或明确返回冲突供重试，不能都报告成功却丢数据。现有测试是在保存前先完成“并行修改”，只验证旧客户端，不是请求交错。

4. **P2：原页接纳新项目时，旧项目未保存草稿串入。** workbench.js:917–929、3613–3633。boards 只以 profile_id 为键，sync 遇 dirty 直接跳过；adoptPromotedWorkspace 由候选接受路径调用，会在原页更换 exampleId。
   - 独立浏览器检查：A 未保存 [地点,时钟,NPC]，调用实际 adoptPromotedWorkspace 接纳 B 并执行实际 refreshWorkbenchData；当前 exampleId 和 bundle.id 均为 B，但 draft 仍为 A 的三个 ID 且 dirty=true，B 面板出现旧引用。这不是普通书架导航整页刷新场景；复现调用的是生产接纳函数，未构建真实候选任务的端到端接受流程。
   - 修正：草稿/保存状态按真实项目与板块共同隔离；接纳或切换项目时恢复正确草稿或明确处理未保存内容。异步保存应捕获所属项目/板块，请求返回后只能更新原所属数据，不能污染后来打开的项目。
   - 回归：A 脏草稿→实际原页接纳 B→刷新→返回 A；B 不显示/保存 A 选择。再加 A 保存挂起→切 B→旧响应回来，核对 B 的 bundle、草稿、状态和快捷区均不受影响。
