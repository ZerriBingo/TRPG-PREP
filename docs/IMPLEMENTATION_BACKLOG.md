## R2：跨页候选复核与事实提升

目标：让真实候选经过 GM 审核后成为可用于产物生成的事实，同时保留完整来源和历史。

### R2.1 多页复核

- 候选按任务、场景/实体聚类和范围交集组织。
- 支持在同一复核上下文查看多张来源页。
- 支持编辑全部 `source_refs`，不只编辑第一条。
- 支持拆分错误合并、合并重复候选、标记冲突和未决问题。
- 页码筛选接受范围表达，并按引用交集匹配。

### R2.2 显式提升

- “接受”只完成审核；“提升为事实”是第二个明确命令。
- 提升时选择 `source_fact` 或 `inference`，并保存 candidate/review 来源。
- 重复提升幂等；冲突提升被拒绝并给出可理解原因。
- 未提升或已拒绝候选不能被卡片和场景计划引用。

当前实现（2026-08-27）：单条接受/拒绝后保持待复核筛选并自动前进到下一条，只有整个待复核队列清空后才转到已接受列表；批量“复核所选”和“送入书架”已拆成两个独立阶段。候选可按整个备团任务跨多个分析窗口汇总，批量复核在服务端校验候选归属；来源页筛选支持单页、页码范围和离散页，并按候选来源引用交集匹配；单条与批量事实提升已接入独立任务书架；`source_fact/inference`、完整来源、candidate/review provenance、幂等冲突和任务删除后的审计保留已通过回归。尚未实现候选拆分、合并、冲突标记和全量多来源编辑。

阶段验收：

- 至少一条批准事实同时引用两个不同页码。
- 编辑、刷新、重启后来源版本和审核历史不丢失。
- 能从真实候选提升事实，无需手工重新输入同一文本。

## R3：批准事实到现实恐怖单元包

目标：让 LLM 从已批准事实生成可复核的现实恐怖备团产物，而不是要求 GM 手工制作所有卡片。

当前实现（2026-08-28）：书架可显式调用当前模型创建持久化 `artifact_job`。小事实集直接生成；大事实集按中英混合 token 与字符预算分批做局部事实整理，再由一次全局规划对齐实体和跨批关系，最后逐张计划卡回读其引用的原始已提升事实落卡。局部摘要不是新事实来源。`artifact_job_steps` 保存输入哈希、每次尝试、响应、错误与规范化输出；重试会复用成功步骤，仅补失败步骤。所有卡片通过事实引用、字段来源、卡型契约与运行锚点校验后才原子写入。书架与分析版本已分离：重新分析沿用同一 `workspace_id` 并生成 `v2/v3`，项目删除级联清理所属分析版本。候选批量复核前端按 100 条自动分批，后端兼容最多 1000 条的旧缓存请求并格式化结构化错误。机械窗口只展示固定页数、字符预算或范围末端等真实原因，标题等只显示为“非分段”诊断信号。284 条奈面事实已在数据库副本中完成 3 个局部批次、20 个局部单元、1 次全局规划、4 张最终卡和失败步骤续跑验证；当前真实上游已用 6 条事实在副本中生成 3 张卡。完整章节真实产物仍待 GM 验收。详见 `MAINTENANCE_2026-08-28_HIERARCHICAL_ARTIFACTS.md`。
