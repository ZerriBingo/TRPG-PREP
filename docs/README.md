## 文档约定

- **决策**：已经选择的方向；实现可以直接依据它推进。
- **假设**：为了推进试点而暂时采用，必须在真实跑团或对照测试后复核。
- **待验证**：没有足够证据，不应被写成 schema 硬约束。
- **历史**：曾经有效但已被新决策取代的说明，只用于理解为何现在这样设计。

## 维护规则

- 每次改变产品边界、板块卡型、LLM 权限或验收标准，都在 `REASSESSMENT_*.md` 或新的决策记录中写明日期、动机、被取代的判断和影响面。
- 任何模型生成内容都必须能回溯到源页或明确标记为 GM 创作；不能把“模型觉得合理”写回原文事实。
- 新增规则档案前，先完成一个真实小章节的运行验证；没有真实使用场景的档案不进入代码。
- 代码测试通过不等于产品决策通过。若测试结果与 GM 实际阅读负担冲突，暂停扩展并记录冲突。
- 复核队列、生成器或运行器不能脱离上下游单独标记为产品完成；从空白数据库完成真实工作流才算通过阶段验收。
